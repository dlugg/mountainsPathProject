# Mountains Path Project

A hiking route planner built on real OpenStreetMap data. You give it a list of places —
for example `Kuźnice → Murowaniec → Czarny Staw Gąsienicowy → Kasprowy Wierch → Kuźnice` —
and it finds the route along actual hiking trails, estimates the walking time and exports
the result to GPX, ready to open in mapy.cz or any hiking app.

I started it because finding a good route through several points in the Tatra Mountains
by hand is tedious, and I wanted a tool that I would actually use myself.

## What it does

- **Reads OpenStreetMap data** (Overpass API export) into Java records with Jackson
  and builds a graph of trails: `path`, `footway`, `track` and `steps`.
- **Respects one-way trails** (`oneway=yes`), e.g. the one-way section of Orla Perć.
- **Estimates walking time** with the Munter method: horizontal distance plus ascent
  and descent. Elevations come from the EU-DEM 25 m model via the OpenTopoData API,
  so uphill and downhill along the same trail take different time.
- **Finds a route through mandatory points** by place name (`name` / `name:pl` tags),
  snapping each place to the nearest trail vertex.
- **Uses Dijkstra's algorithm with a priority queue**, generic over the vertex type.
- **Exports the route to GPX.**

## How I checked that it works

- **Real hike.** The route Kuźnice → Murowaniec → Czarny Staw → Kasprowy Wierch → Kuźnice
  generated by the program is 18.7 km. My own track of the same hike is 18.9 km in mapy.cz
  (19.5 km measured by my Garmin watch), and both lines follow the same trails on the map.
- **Trail signs.** The pace and the descent factor of the Munter formula are calibrated
  against the official walking times on PTTK trail signs (Kuźnice ⇄ Murowaniec).
- **Performance.** Replacing the linear minimum search in Dijkstra with a priority queue
  made a four-leg route on ~9,000 trail vertices about 10× faster (~2 s → ~0.2 s)
  without changing the result.
- **Unit tests** (JUnit) run on a small OSM extract around Murowaniec stored in
  `src/test/resources`; expected values were calculated independently, not copied
  from the program output.

## How it is organised

| Class | Responsibility |
|---|---|
| `OsmReader` | reading OSM and elevation files, indexing nodes by id |
| `OsmGraphBuilder` | building the trail graph, edge weights, one-way rules |
| `Geo` | distance between coordinates, Munter walking time |
| `PlaceFinder` | finding a place by name, nearest graph vertex |
| `RouteFinder` | Dijkstra, path reconstruction, route through several points |
| `Gpx` | GPX export |
| `ElevationDownloader` | one-time download of elevations for all trail vertices |

## Running it

Requirements: Java 26, Maven.

1. Download trail data with the query from `src/main/resources/overpass-query.txt`
   (for example in overpass-turbo.eu → Export → raw OSM data) and save it as
   `src/main/resources/export.json`.
2. Run `ElevationDownloader` once — it creates `src/main/resources/elevation.json`.
3. Set the list of places in `Main` and run it.

Both data files are generated and not stored in the repository.

```bash
mvn test
```
